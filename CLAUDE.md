# CLAUDE.md

## What this repo is

**Mist** is Johnny's personal macOS browser, a fork of Phi Browser (`phibrowser/phibrowser-mac`, Apache 2.0). He adds the features he wants, removes the ones he doesn't, and replaces Phi's AI with his own. Nothing here is upstreamed.

- Only `main` lives on `origin` (`BullDF/mist`, private).
- The tree is published to the public `BullDF/mist-public` as squashed snapshots, one commit each, never this repo's history. Publish only when Johnny asks: first `git grep` the tree for every identifier in Drifter memory `mist-private-ids`, then `git fetch git@github.com:BullDF/mist-public.git main`, `c=$(git commit-tree 'HEAD^{tree}' -p FETCH_HEAD -m "Update Mist to <date>")` with `GIT_AUTHOR_*`/`GIT_COMMITTER_*` set to `Johnny Meng` and `106421874+BullDF@users.noreply.github.com`, and `git push git@github.com:BullDF/mist-public.git "${c}:refs/heads/main"` (braced: zsh reads `$c:r` as a modifier).
- Because of those snapshots, never commit personal identifiers (email addresses, account and workspace names, Slack IDs, absolute home paths, machine names, employer details), in code, tests, docs, skills or commit messages. What agents need of them lives in Drifter memory `mist-private-ids`; fixtures use `example.com` names.
- No PRs: commit straight to `main`. After an upstream sync rewrites `main`, push with `git push --force-with-lease`.
- Commit messages are one concise summary line: no bullets, no body.
- Removing a feature means deleting its code, state, UI, strings, project entries and the tests that only covered it. Never hide it behind a flag or leave dead code.
- Found-but-deferred work goes into a GitHub issue on `BullDF/mist`; `gh` needs no `gh auth switch` here.
- Never open anything against upstream, and never write `phibrowser/phibrowser-mac#N` (it posts a backlink on upstream's issue).
- Upstream owns `docs/`; don't edit it. Fork guidance belongs here.

## What's closed

- **Engine:** Chromium is a closed prebuilt, `Frameworks/Phi Framework.framework` (gitignored). The client can use only what `Sources/ChromiumBridge/PhiChromiumBridgeHeader.h` exports.
- Chromium owns windows and the tab list; Swift mirrors them through bridge callbacks.
- To see what a framework ObjC method does: `otool -arch arm64 -oV` lists the implementing class (e.g. `WebContentWrapper`), its selrefs (section `addr` + 8 × index) and imp addresses; disassemble an imp with `xcrun llvm-objdump --arch=arm64 -d --start-address=…`.
- Chromium encrypts cookies and saved site data with the keychain item `Phi Safe Storage`, a name compiled into the framework, so main, Dev and tests share it. Never delete it.
- Crash evidence: `.ips` reports in `~/Library/Logs/DiagnosticReports` and its `Retired/` (pruned after about a week), minidumps in the data folder's `Crashpad/pending`, and `Phi/PhiLogs/` (rotates within days). Framework frames are unsymbolicated: match two crashes by their frame offsets. An uncaught ObjC exception's `.ips` (`_crashOnException`) holds no reason or throw backtrace; `/usr/bin/log show --predicate 'processID == <pid>'` around the crash has both. Symbolicate Mist's frames per the live-check reference (`dsymutil`, then `atos`).
- Browser-process memory: all malloc, Swift's included, lands in PartitionAlloc (`footprint`'s "App-Specific Tag 14"), whose zone `heap` and `leaks` can't read. The framework has no heap profiler (`--memlog` isn't compiled in), so nothing attributes an allocation to its caller: bisect by workload in Dev. Take a memory-infra dump over the agent CDP socket instead (`Tracing.start` with `disabled-by-default-memory-infra`, then `Tracing.requestMemoryDump`, `levelOfDetail: detailed`) and read `malloc/partitions/allocator/buckets/*`; the browser target has no `Memory.startSampling`.

## Build and install

The only scheme is **`PhiBrowser-OpenSource`**, with the single configuration `OpenSource` (`Configs/OpenSource.xcconfig`).

```sh
./scripts/download_phi_framework.sh --version v2.19.0  # framework into Frameworks/
mist/scripts/install.sh --dev                    # build, replace and relaunch /Applications/Mist Dev.app
mist/scripts/install.sh --dev --seed --no-launch # copy main's settings and data into Dev
mist/scripts/install.sh                          # main /Applications/Mist.app, only when Johnny asks
```

- Preview every change in **Mist Dev**; agents verify live only in Dev, never main. When a task forbids launching browsers, use `--dev --no-launch` and verify the built product statically.
- Bundle IDs, which also name the defaults domain and the `~/Library/Application Support/<id>` data folder: main `com.bulldf.mist`, Dev `com.bulldf.mist.dev`, tests `com.bulldf.mist.tests`.
- The build product stays `Phi.app` with executable `Phi`: `TEST_HOST` and `Phi-Swift.h` depend on `PRODUCT_NAME`. `install.sh` renames the installed copy.
- The app's code must stay in `Phi.debug.dylib` behind Xcode's stub executable: keychain and privacy grants trust the stub's ad-hoc cdhash, so a changing executable prompts for the keychain password after every install.
- Never downgrade the framework below a version Mist has already run: Chromium won't open a newer profile.
- The framework carries only its Chromium version. The download script records the release tag in `Frameworks/PhiFrameworkRelease`, which `rebrand_app.py` stamps into the built app's Info.plist (`PhiFrameworkRelease`) for the About window; a framework installed any other way shows no tag.
- SwiftPM dependencies live only in `PackageCollection/Package.swift`, not on the app target.

## Tests

```sh
mist/scripts/test.sh -only-testing:PhiBrowserTests/SomeTestClass # or .../SomeTestClass/testMethod; --keep-state keeps data
```

- Run hosted XCTest only through `mist/scripts/test.sh` (tests bundle ID, fresh settings and data), never raw `xcodebuild test`.
- Compile-only, no windows: `xcodebuild build-for-testing -project Phi.xcodeproj -scheme PhiBrowser-OpenSource -destination platform=macOS -derivedDataPath build/DerivedData-Tests MIST_BUNDLE_ID=com.bulldf.mist.tests`.
- `PhiBrowserUITests` can't run on this Mac (macOS kills the ad-hoc-signed runner); only compile them.
- Hosted tests pop real windows onto Johnny's screen. Run only the classes that cover the change, never the full suite unless he asks. After a full-suite run, append a row to `mist/full-suite-runs.md`.
- Prefer a hostless check for new pure logic: `build-scripts/test-*.sh` compile only the files they list with `swiftc` (see `docs/testing.md`). The `*-live.sh` ones need `MIST_LIVE_CLAUDE=1` or `MIST_LIVE_CODEX=1`; `test-sidebar-footer.sh` shows a small window.
- Hostless scripts slice sources at marker comments (`// MARK: - …`) and compile the `Tests/<Name>/` harnesses outside Xcode, so neither the Xcode build nor Periphery sees what they use. After deleting or moving code, also run the non-live `build-scripts/test-*.sh` (`test-sidebar-media-ui.sh` needs a fixture server and the app).
- Dead-code sweeps: Periphery (`brew install periphery`) scans the index of a `build-for-testing` with `COMPILER_INDEX_STORE_ENABLE=YES` (`--skip-build --index-store-path …`). Beyond the hostless harnesses, it doesn't see uses in the `PhiTimeMachineInstaller` target (`Application/TimeMachine/`), and it flags test hooks and fields used only by synthesized `Equatable`/`Hashable`, which stay.
- A test that creates an `NSWindow` or `NSPanel` must set `isReleasedWhenClosed = false` before closing it, or the host crashes in a later test. Setting its `contentViewController` shrinks it to the controller view's frame (zero for a page), so a test that measures layout sets the content size afterward.
- `SpaceSessionControllersManager.getAllWindows()` skips dormant controllers, so a test's dormant `SpaceSessionController` never reaches code that walks windows (the shared `AgentChatStore`'s tab closures); give such a test its own store with closures over its state. A chat page's composer joins the window only once the page's hosting view lays out (`layoutSubtreeIfNeeded`), so lay it out before making the composer first responder.
- Get a UserDefaults suite from `makeTestDefaults()`: a suite named in `~/Library/Preferences` leaks its plist, which cfprefsd writes back after deletion.
- Offscreen SwiftUI hosts expose no accessibility tree; assert on model values or measured sizes.
- The test host is never the active app, so its windows are never key and a posted mouse-down only focuses the window, never reaching the view: call the view's `mouseDown(with:)` directly (`testPlainClickOnExpandedPeerMessageTextCollapsesIt`).
- Hosted classes run alphabetically in one process, so an order-dependent failure comes from a class sorting before it.
- `ClaudeCodeModelCatalog.shared` fills from the real `claude` CLI during a hosted run, so a model chip's label (and width) differs between a test run alone and one late in a class: size layouts from the chips' measured widths.
- `leaks` can't attach to the test host (no `get-task-allow`); find what outlives a test with weak-reference probes checked in `class func tearDown()`.
- No linter or formatter config; run `git diff --check` before committing.

## What `PHI_OSS_BUILD` changes

- Mist's sources have no `PHI_OSS_BUILD` conditionals left; don't add any. The condition stays defined so upstream code behind `#if !PHI_OSS_BUILD` stays dead after a sync until it's deleted.
- It gates the prune build phase: `scripts/prune_open_source_build.sh` strips Sparkle, Sentry, PostHog and Sentinel from the `.app` and fails the build if any remain. Exclude another component there.
- Mist defines neither `DEBUG` nor `NIGHTLY_BUILD`; don't reintroduce them. What upstream gated on them is plain code here, in the branch Mist wants: Developer tools, previews, test hooks and `.all` logging stay, and persisted names keep their canary values (`vault-session-canary`, the `canary` agent-space channel).
- Chromium runs sandboxed: never pass `--no-sandbox`. `ChromiumLauncher.m` passes `--phi-no-embed-extensions`, so Phi's embedded extensions stay unloaded.

## Mist branding

- `mist/scripts/rebrand_app.sh` (end of `prune_open_source_build.sh`) rebrands the **built app only**: bundle name, `Phi` → `Mist` in compiled strings, the framework's paks, the blanked Sentry crash-upload URL. Sources and `Frameworks/` stay untouched.
- `rebrand_app.py` compiles every English catalog value into `en.lproj` (`xcstringstool` skips entries marked `new`), and fails the build when a Swift fallback saying `Phi` has no catalog entry.

Find it with `mist/scripts/pak.py <pak> list --find '<marker>'` (`<ntp-app>`, `phi-games-js`, `id="phi-product"`), raster logos by extracting the scale-pack PNGs, the Crashpad URL with `strings -a`; then update the ID or hash constant.

- Compatibility values (backup-name matching, identifiers, keys, paths) intentionally stay `Phi`.

## Framework facts

- Chromium reads unforced keys in the app's defaults domain as recommended policies (`MistChromiumAutofillPolicy` uses this).
- ⌘⇧T reopens a tab at its old strip index, except into a group still open, where Chromium puts it at the group's end; `BrowserState` remembers grouped tabs' slots at `tabWillBeRemove` and moves the reopened tab back.
- Chromium drops fragments and queries on `chrome://newtab`, so agent chat tabs live at `file://<app data>/MistApps/Drifter/<uuid>.html` (chats from before #71 at `MistAgents/Chats/<uuid>.html`).
- Read Chromium's `History` only through a temporary copy (`BrowsingHistoryProvider`), never the live file.
- Session restore gives every tab group a new token but keeps its title, so a group is recognized across a relaunch by its title: Drifter's agent tab folders end theirs with U+2060 (`BrowserAgentFolderState.titleMarker`).
- A tab's `custom_value` (`guidInLocalDB`) rides session restore, which skips a second tab with the same value. A non-empty value also bounces cross-domain loads into new tabs and blocks tab groups (except `phi-peek` namespaces), so it can't key an ordinary tab.
- The wrapper's `reload`, `reloadBypassingCache` and `stopLoading` act on the window's active page (or presented peek), whatever tab they're called on; `goBack`/`goForward` act on their own tab. Target a tab with `Tab.reloadPage` / `Tab.stopLoadingPage` (CDP).
- `BrowserState.focusTabWithTabId` / `focuseTab` only mirror Chromium's own active-tab change; to switch tabs, call the tab's `webContentWrapper?.setAsActiveTab()`. Mirroring alone leaves Chromium on the old tab: its title stays on the window and ⌘W closes it.
- `Tab.close()` on a tab Mist still marks active sends `IDC_CLOSE_TAB`, which closes Chromium's active tab, and Mist's mirror of a switch arrives later. So when switching away from a tab you'll close, close it first: closing it right after `setAsActiveTab()` on another tab closed that other tab (the app tab `openApp` had just focused).
- Mounting a background tab's `nativeView` anywhere under the window's content container makes Chromium treat it as visible: it paints and runs rAF, even inside a zero-size `masksToBounds` view, which the surface draws none of. A background tab never shown draws nothing yet reports `visibilityState` `visible`, and `Page.startScreencast` sends it no frames.
- Every web view draws on the window's content surface, below all tab views, so a native fill above it hides the page.
- Tabs in a covered window or on another Space are hidden and run no rAF: wheel events and synthesized scrolls never apply, and CDP `mouseMoved` acks take ~5 s. Presses, keys, `insertText` and captures work; `--disable-backgrounding-occluded-windows` changes nothing.
- AppKit bounds scaling is ignored; only CDP device emulation scales a page, and Mist never applies it to a tab.
- A clipped `Page.captureScreenshot` swaps in device metrics for the capture, which shows on a visible page, so the agent's close-ups and full-page captures of one run under a frozen cover from an unclipped capture, kept until two rAFs after. An unclipped capture reads the displayed frame and changes nothing.
- `captureBeyondViewport: true` relays the page out (to 1×1 for ~12 ms) and fires `resize`; use it only for full-page or off-viewport captures.
- The app's own `AppDevToolsPageSession` rides the agents' transport, so its drive commands on user-Space tabs flash the agent operating mask. `Tab.sendPageCommand` claims the report first (`appWillSendPageCommand`); another app session driving a user tab needs the same.
- `addTabsToGroup` puts tabs from before the group at its start and tabs after it at its end. Mist's Add to Group always appends (Johnny's call), through `BrowserState.addTabsToGroupEnd`.
- A tab pinned while open keeps its slot in Chromium's strip but leaves `normalTabOrder`, so a strip move anchored on the next tab Mist shows can land past it. A grouped tab moved there touches no member and Chromium ungroups it: anchor moves into a group on its members (`groupEndSyncMoves`, `syncNormalTabRelativeOrderToChromium(tabId:withinGroupToken:)`).
- `openTabWithUrl:windowId:` reuses an open tab with that URL. A new foreground tab at the end of a chosen window is `routeURLIfSpaceRuleMatches` then `openTabBypassingSpaceRouting…`; external opens (#83, `openExternalURLsInPrimaryWindow`) push a routing table whose window map holds only the primary window around the route call, so a rule-matched link surfaces in the primary slot instead of another window showing that Space.
- `dispatchCommand:window:` gets Chromium's hosted window (`hostedChromiumWindow`), not the shell window holding Mist's views: compare a native view's window with the window controller's `window`. A command the hook misses runs on the hidden page, and Chromium's find bar or zoom bubble draws over a native page. Chromium also validates `commandDispatch:` menu items against the hidden page, so a native page answers them itself (`CommandDispatcher.nativePageZoomEnabled`).
- Chromium's key path takes ⌘V before the responder chain on a native page, so a native page that pastes handles it in `performKeyEquivalent` (Mail compose's editor, the Clipboard page's root view) and keeps a `paste(_:)` action for Edit ▸ Paste.
- Edit ▸ Undo/Redo send `undo:`/`redo:` (tags `IDC_CONTENT_CONTEXT_UNDO`/`REDO`) up the responder chain, so a page controller that answers them for its own history reaches them before the window and must hand a focused text view's to its `undoManager` (Mail's `performHistory`: a text field or the composer undoes its text, everything else message actions). The same commands also arrive as `commandDispatch:`, which `ShellWindow` routes through `CommandDispatcher` (`mailHistoryMenuEnabled`). Mail compose's body editor keeps its own undo manager: WebKit registers edits with the view's `undoManager`.
- Native tooltips (AppKit `toolTip`, SwiftUI `.help`) never show in browser windows; use `setCustomTooltip` / `.customTooltip`.
- In browser windows SwiftUI's `.pointerStyle(.link)` left the hand on after the pointer left the hosting view sideways, and a cursor rect on a subview of an `NSHostingView` never applies (AppKit sends `cursorUpdate` to the hosting view). Set such a cursor from the hosting view itself: tracking areas with `.cursorUpdate`, the arrow on exit and when it hides (`MistAppsWidgetHostingView`). An AppKit control inside a `MistKitHostingView` (the chat composer's buttons) gets the hand by adopting `MistPointingHandControl`, which also keeps its cursor rect for plain AppKit parents. Hit-test a subview with its `bounds` intersected with `visibleRect`: views don't clip to their bounds by default, so `visibleRect` alone reaches past them and left the Clipboard drop area's hand on outside it.
- An `NSHostingView` within the window's top 28 pt (the transparent titlebar's band, e.g. a side panel's header in a vertical-tabs layout) gets that overlap as a top safe-area inset, which pushes centered content down only in some layouts; set `safeAreaRegions = []` on it (the Chat panel header).
- An `NSPopover` holding a SwiftUI hosting view needs `sizingOptions = []` and the view's frame and `preferredContentSize` set before `show`. A popover sized by its hosting view opens tall and shrinks toward its bottom edge, far below its anchor (the chat header's marker list).
- `Page.startScreencast` sends a frame only when the page repaints: a static page sends none, so the agent recorder seeds its first frame with an unclipped `Page.captureScreenshot`.
- Gate captures and screencasts on `BrowserAgentTabPreview.hasLivePage` (no crash page, discarded or unloaded tab). Agents' own commands can't be filtered: `AgentCDPListener` hands their raw socket to Chromium.

## Mist sync

- **Relay** for `Sources/MistSync/`: the Cloudflare Worker `mist-sync` in `mist/sync-server/`, on Johnny's Cloudflare account (account and URL in Drifter memory `mist-private-ids`). Redeploy with `npx wrangler deploy` there.
- A new data kind only adds a source (like `MistBrowserDataSyncSource.swift`); the wire protocol and engine stay unchanged. A Mac whose Mist predates a kind stops syncing on its first record (`unknownKind`) until it's updated.
- Remote changes apply through the state layer (`SpaceManager`, `ProfileManager`, LocalStore bookmark APIs), and changes caused by applying them are never reported back.
- The relay caps a record's blob at 64 KiB and a push at 500 records; Cloudflare caps a received WebSocket message at 32 MiB. Larger payloads go as chunk records, like the shared clipboard (#70).

Shared clipboard (`MistClipboardSyncSource`, kind `clipboard`), shown by the Clipboard app (`ClipboardApp`, page in `Sources/UserInterface/WebContent/Clipboard/`), Johnny's decisions:

- Text, images and files (one per item) up to 10 MB, end-to-end encrypted, in one slot: each send replaces the item on every Mac, and Clear removes it everywhere.
- An item expires 5 minutes after it's sent and can't be copied or dragged after; its content leaves the relay as tombstones.
- A file item has a Download button and never drags; text and images drag. Download saves the file to `~/Downloads` under its sent name (Chromium's `name (1).ext` when taken), and the button then reads Show in Finder while that file is there. Copy of a file and copy or drag of an image write it to `MistSync/Clipboard/Copied/`, kept until a newer item replaces it.
- A click on the box (empty or staged, pointing hand over it) opens a one-file chooser sheet; the chosen file stages exactly like a dropped one and replaces any staged item. ⌘V pastes into the box whenever the page or nothing has focus, never while another view (the address bar) has it.
- The whole box lives in the Clipboard tab; Settings ▸ Sync keeps only the “Share with your other Macs” switch, per Mac (defaults key `MistClipboardSharing`, never synced) and on by default. Off refuses sends and clears, shows nothing and deletes local item content, but keeps tracking heads and tombstoning the Mac's own slot, so ordering holds. Turning it back on shows only items sent after that (`State.visibleAfter`). The tab's not-set-up and sharing-off states each link to Settings ▸ Sync.

How it works:

- Each Mac writes only its own slot, keyed by the engine's `deviceID`: a head record plus 32 KiB chunk records. The owner tombstones its slot when its item expires or a newer head (a send or a clear marker) arrives, so no record ever has two writers.
- Order is `(sentAt, slot)`, with `sentAt` kept above every head seen. Expiry counts from `min(sentAt, local receipt)`, so a skewed clock can't extend an item.
- A 10 MB item is one push of about 18 MB, which the deployed relay accepted.

## Mist passwords

Mist's own password manager (`Sources/PasswordManager/`) also keeps email addresses with no password. Johnny's decisions:

- Email addresses are added and removed only by hand in Settings ▸ Passwords. Forms never prompt to save one, and submissions never add one.
- The dropdown lists them below the site's logins on a username field (a `type=email` one included), and alone on an email field outside a login form. A password field never shows them. Choosing one fills only the focused field. They sync to every Mac (kind `email`).
- Verification codes come from Mist Mail (`MistMailCodeSource`): codes in any account's Inbox from the last 10 minutes, sender-domain matches first, at most 3. A code field shows nothing until a code exists, then updates live as mail arrives. Filling one marks its email read, moves it to Trash (never a permanent delete) and removes its notification. The "Autofill passwords" switch gates it.

## Mist apps

Mail, Drifter and Clipboard are apps (#71): standalone features shown as ordinary tabs, a native page over a placeholder `file://` page. One layer serves them all, in `Sources/MistApps/`.

- `Core/` is Foundation only, because hostless scripts compile it: `MistAppID` (Clipboard, Drifter, Mail; its alphabetical order is the order in every launcher), `MistAppRoute` and the placeholder HTML. The app target holds the `MistApp` provider and `MistAppPage` page protocols, the `MistApps` registry, the open rule (`BrowserState.openApp`), the placeholder writer and the providers in `Apps/`.
- URLs: `file://<app data>/MistApps/<Name>/index.html` for every app's page (Drifter's home included), `…/MistApps/Drifter/<UUID>.html` for a chat. `MistAppRoute.resolve` also recognizes the legacy `MistMail/Mail.html` and `MistAgents/Chats/<UUID>.html` forever; nothing migrates them. App data stays outside `MistApps/`.
- Ask whether a tab shows an app with `MistApps.address(url)` (URL only) or `Tab.appAddress` (nil in an incognito window, for presentation); never match paths by hand. `isMistApp` in `mist-browser-mcp.mjs` mirrors the layout and must follow any change to it.
- Adding an app: a provider in `Apps/`, an entry in `MistApps.all`, an `openCommand` (its Apps menu item's tag, also listed in `Shortcuts.Group.apps` so Settings ▸ Shortcuts shows it as an assignable row with no default key (Drifter's ⇧⌘D and Mail's ⇧⌘M are Johnny's picks), plus its cases in the Shortcuts title and description switches), and its name in `test-mist-apps.sh`'s catalog guard.
- Drifter (`DrifterApp`) is the one app with instances (`MistAppID.hasInstances`): a single home page (`DrifterHomeViewController`, `MistAppAddress` with no instance) plus one instance per chat ID (`MistAppAddress.chatId`). `makePage(_:)` gets the address, and a tab moving between the home and a chat gets a new page controller. `AgentChatRoute` keeps the chat data paths while delegating URLs to `MistAppRoute`. A chat's placeholder is its legacy file if that exists, else its canonical one (`placeholderURL(for:)`); every write and read goes there. Chat placeholders follow the theme through `MistAppPlaceholders`, which rewrites only chats with an open tab.

Design kit (#73): `Sources/MistApps/Design/` holds the apps' one design language, tokens in `MistKit.swift` (colors, radii, type, elevation) and every component in SwiftUI, with AppKit counterparts for AppKit pages. An app page draws every visual piece from the kit: a missing piece is added to the kit, never styled inside an app. The theme color is the only accent (filled buttons use `.themeButtonBackground`); everything else is themed grayscale. Every outlined surface draws `MistKit.borderWidth` (1 pt) in the soft `mistHairline`, never a pixel hairline (Johnny's call: hairlines read too thin); pane dividers stay hairlines. SwiftUI pages host in `MistKitHostingView`, which sets the pointing hand over kit buttons and makes the theme color SwiftUI's tint. A list whose rows come, go or change places animates only those changes: publish them through `MistMotion.changeList` (which snaps under Reduce Motion) and give the rows `.transition(.mistListRow)` and `.mistListPosition(index)`, which slides a moved row over the rows it passes and keeps its text on it; a row updating in place never animates.

Johnny's decisions on the kit:

- Kit components stay even while no app uses them (`MistNotice`, `MistSectionHeader`, `MistSidebarRow`, `mistRow`, `mistSidebarBackground`): they're there for future apps' designs.
- A piece unique to one app that the kit doesn't have stays app-local only while it aligns with the kit: its tokens, states and components (`MistMenuButton`'s chips match `MistPopUpButton`). One that doesn't is rebuilt from kit tokens and components, with a new kit component when nothing fits. Hand-laid list rows (the `/` and `@` popups, the Mount to Tab picker) take the kit's row radius and the gray `mistSelectedFill` for their highlighted row, never the theme color.

A page without a prototype (the New Tab Page was the first) follows the rules the prototyped pages share:

- One centered column, `MistKit.readableWidth` wide (24 pt gutters when the pane is narrower). It opens with the page header (`MistPageHeader`/`MistPageHeaderView`): the app's glyph, or a raster logo at its own size through `.image`, titled only when the page has a title.
- The hero is the page's primary action, about 34 pt under the header: a text input goes in the composer card (`MistComposerCard`, `.input`), a box to drop or fill in a `.hero` card. Nothing else floats as high.
- Below the hero, 26–32 pt down, other content takes the card its kind gets: one item a `.content` card, a row inside a card or a file an `.inner` card, an activity entry a `MistTileCard`. Launchers (apps, places) are `MistLauncherTile`s with no card, and placeholders stay plain text.
- States come from the kit, in gray: hover `mistHoverFill`, pressed and selected `mistSelectedFill`. The theme color marks only the primary action, focus, selection and progress. A page's text field claims its field editor (`MistFieldEditors`) for the caret and selection.
- The address bar's surfaces use the kit too (#76): the omnibox's suggestion rows are kit list rows (`OmniBoxSuggestionRowView`, laid out like the `@` rows), shared by ⌘L and the New Tab composer, which must stay identical, and the ⌘L panel is a `.floatingInput` card. Its `…` menu (an `NSMenu`) and Chromium's bubbles (site info, bookmark star, zoom, passwords) aren't Mist's to restyle.

The apps never show the macOS accent color (Johnny's call). A native field's selection and caret come from its window's shared field editor, so kit fields claim it through `MistFieldEditors` (wells, `MistSelectableLabel`, the find bar), which styles it while they edit and hands the selection back after; an app's own `NSTextView` calls `applyMistSelection()`. Links stay `NSColor.linkColor` (SwiftUI text links pin it with `.tint`): the theme color is too pale for text in some themes. No public API colors `NSTokenField` tokens (the token cell is private), so Mail's recipient tokens keep AppKit's own blue, whatever the accent.

Johnny's decisions, not to be reverted:

- App names are English in every language: `MistAppID.name` literals, never catalog strings, and a translated sentence that names an app keeps the English name.

Transcript performance (#38, #41, #46): per update, work must scale with what changed.

- The transcript renders only rows within half a screen of the viewport (`AgentChatTranscriptScroll`); its hosting view gets a new root only when the `AgentChatTranscriptSlice` value changes.
- Row heights are lazy: only rows about to render are measured at once, the rest hold an estimate (their last height, else their kind's average) until idle slices measure them, and a height change above the viewport moves the scroll position with it. Never measure every row synchronously in production (`finishMeasuring()` is for tests): on a 657-item chat that blocked the tab switch for seconds. A test asserting an exact total height calls `finishMeasuring()` first.
- Row IDs can repeat in a transcript, so never build a dictionary of rows with `uniqueKeysWithValues`.
- A row's height may depend only on its row value, spacing, open flag, marker and `AgentChatTranscriptViewState`; a new view-state set must join the height key, and anything a rendered row reads must be in the slice.
- Overlays that never size a row (hover buttons, the marker button) stay out of the measurer's tree (`agentChatMeasuring`), which re-measures the streamed reply on every update.
- A child chat's preview card is a bitmap of its last rows (`AgentChatMiniatureView`), never a live transcript: drawn from a windowless SwiftUI tree the card keeps (a windowless host's timelines never tick), on a status change and at most every 2 s while the child runs, only while the card is on screen, never within 0.4 s of a scroll or key press, and 0.25 s apart across cards. A render costs about 11–15 ms.
- The transcript answers `mouseDownCanMoveWindow` false. AppKit's under-titlebar drag pass ignores that and walks every view in the titlebar band after any frame change in the window.
- The page's hosting view has no `sizingOptions`, the header's info row is an Equatable value view (`DrifterChatHeaderInfo`), and a running agent's transcript updates apply 100 ms apart.
- Only the transcript is throttled: `AgentConversation.update` republishes `status`, `items`, `outputTokens` and `backgroundTasks` on every streamed chunk, dozens of times a second. A subscriber that does work takes `removeDuplicates()`, and nothing writes a store-level published property per update: one `unseenCompletions.remove` per chunk refreshed every store observer, each tab's sidebar status included.
- No `UserDefaults` write on a per-update path or in a getter: every write, even removing a missing key, posts `didChangeNotification` to about 25 observers across the app (sidebar, layout, header). `DrifterLaunchSettings.config`'s legacy cleanup once wrote nine per read, from the Chat panel's refresh on each store change, and saturated the main thread while an agent streamed.
- The composer runs on every keystroke, so its work must not scale with the draft: a 28 KB pasted command once cost 330 ms a key. Scan the text through `MistPromptEditor.text` (`scanText`, a native copy cached per character edit) and the cached `slashTokens`/`codeBlocks`, never Swift character walks over `textView.string`, which bridges to slow per-character paths. `restyleCommands` styles a copy and writes back only the runs that differ, and a mirrored draft replaces only its changed span: setting attributes or text over the whole storage relays out all of it.
- A row's text view is filled before SwiftUI gives it a width, and laying it out then (a 1 pt container, one character per line) cost 110 ms for a 28 KB command each time its row was rebuilt: nothing forces a row's layout before it has a width (`updateCodeControls` waits for one). `AgentChatTextContainer.lineFragmentRect` runs once per line fragment, so its work per call stays bounded (`hardLineRemainder` stops at `scanLimit`), never proportional to the paragraph.
- `AgentChatRichText` edits only the changed tail of its text storage (`NSTextStorage.apply(_:over:)`); a full `setAttributedString` per delta lags the whole window.
- `MarkdownRenderCache` reuses block pieces by index. A reused piece keeps its `NSTextBlock`s: their equality is identity, so fresh ones break `apply`'s equal prefix. Math attachments compare by value for the same reason.
- Find in a chat matches row values, so `AgentChatTranscriptScroll.searchableText` must be exactly the string the row displays.
- A paragraph's lines render as U+2028 but parse as real line breaks: parsed with U+2028, inline markdown linked a line-ending URL into the next line's first word.
- `MarkdownMath.swift` stays free of SwiftMath, which the hostless scripts can't import.
- SwiftMath (1.7.3 is its latest) lacks common LaTeX (`\bigl`…`\Bigr`, `\lvert`, `\dfrac`, `\operatorname`), and a formula it rejects shows as source: `MarkdownMath.normalized` rewrites such input into what it parses, so add new cases there.
- NSTextTable's automatic layout splits a table's width evenly, so `MarkdownTextTable` sizes columns from their content at layout time (`rect(for:…)`), which first runs at a provisional width.
- NSTextView's copy asks `writeSelection(to:types:)` for legacy type names (`NSStringPboardType`, NeXT RTF), not `.string` / `.rtf`.

## Conventions

- Search the checkout with `rg` or `git grep` for a specific identifier, never `grep -r` for a generic word: `grep -r` crawls the gitignored `build/` (about 18 GB of DerivedData) and `Frameworks/`, and stalls a session for minutes.
- The app menu's About/Hide/Quit items come from Chromium's localized resources, not this repo.
- `IDC_*` command IDs are hand-copied from Chromium; `scripts/check_command_ids.py` checks them against a Chromium header.
- Default shortcuts (#66): a dropped default goes into `Shortcuts.disabledShortcutCommands`, which takes the command off Settings ▸ Shortcuts' list (never an unbound row, Johnny's call) and clears its Chromium aliases; the command stays in its menus. Native menu keys Mist releases are in `releasedNativeShortcutActions`. A Mist default that differs from Chromium's built-in key goes in `productDefaultCommands`, or Chromium keeps its own. Settings' warning that a key conflicts with a macOS system shortcut is no reason to change a default (Johnny's call): ⌘M and ⇧⌘F show it and still reach Mist.
- Every new tab opens at the end of the normal tab list, whatever opened it: links, ⌘T, Mail's links (#82, Johnny's call). The exceptions stay: Duplicate Tab right below its source, ⌘⇧T at the old index, agent tabs in their chat's folder, New Tab in Group in its group.
- A pinned row's `title` is the page title captured at pin time, shown while the tab is closed; a name the user gives it lives only in `overrideTitle`, the sole source of a pinned `Tab`'s `storedTitle`. Writing a name into `title` freezes the live tab's title.
- A tab in a tab group remembers the URL it joined with as its start page (`GroupedTabStartPage`, set from `Tab.updateGroupMembership`). While it has drifted, its sidebar row's icon wears a return arrow and a click on the icon navigates it back in place; the tab menu's "Set Current Page as Start Page" replaces it. The menu bar's Tab menu has both for the focused tab, Return to Start Page ⇧⌘H and Set Current Page as Start Page ⇧⌘S (Johnny's keys), in sidebar layouts only; otherwise the key stays with the page. Johnny's decisions: in memory only, so a relaunch takes each tab's current page; a tab that leaves its group forgets it; pinned, bookmark-backed and app tabs and agent folders never get one; no UI in the horizontal strip.
- New Settings panes copy General: section title above its card in 12 pt `.textSecondary` (`GeneralSectionView`), `SettingsDetailCard` rows with a 13 pt label left and the control right, regular-size buttons.
- `phi` theme bindings are keyed by key path, which includes the receiver's static type: binding one property through `NSButton` and through a subclass creates two bindings that overwrite each other.
- A build warning that a method "nearly matches" a protocol requirement is a bug: AppKit never calls that method.
- A block observer (`addObserver(forName:…)`) stays registered until `removeObserver(token)`; releasing its token removes nothing. Each one left behind slows every later observer removal in the app, so after hours every freed text view cost milliseconds and long chats scrolled badly (`ThemeManager.subscribe` leaked one per theme binding). Prefer a Combine sink, which ends with its cancellable.
- An `NSTableView` with `style = .fullWidth` puts 20 pt above every group row after the first. Measure such a table's content from `rect(ofRow: last).maxY` (valid right after `reloadData`), never by summing row heights: ⇧⌘A clipped its last row that way.
- SwiftUI lays out an `NSViewRepresentable` by its alignment rect: a borderless `NSButton` insets it 4 pt above and 3 pt below, so its frame (and a layer fill) grows past the SwiftUI frame. Such a button overrides `alignmentRectInsets` to zero (the transcript's marker and copy buttons).
- SwiftUI's selectable text (`.textSelection(.enabled)`) is an AppKit view (`AppKitTextInteractionView`) that takes its clicks before any SwiftUI gesture, so an ancestor's tap never fires over it; catch such clicks with a local event monitor (`AgentChatTranscriptScroll.noteClick`). Its selection reads through `accessibilitySelectedTextRange()`. It shows the I-beam over its links too and exposes no glyph frames, so `MistKitHostingView` finds a link under the pointer by laying out its accessibility attributed string again with TextKit (`MistSelectableTextLinks`), which matches SwiftUI's layout exactly. An `NSTextView` takes its mouse-up in its own tracking loop, which no local monitor sees, so `AgentChatTextView` hands it to `noteClick` itself.
- A momentary `NSButton`'s cell flips its `state` on every click, past an override's `state` observer, so a control that draws its state does so only for toggle types (`MistIconButton` records `setButtonType`). A hover kept from `mouseEntered`/`mouseExited` is read again from the pointer in `updateTrackingAreas`, since a rebuilt area sends no exit for a pointer it already lost (a layout moved the view away). Never give a rebuilt area `.assumeInside`: it lost the exit after a click.
- Never pass a synthesized event of another type to a view's `cursorUpdate(with:)`: `NSTextView`'s reads `event.trackingArea`, which raises on a non-tracking event, and it crashed the app. Leaving a control that floats over the transcript, AppKit gives the cursor back to the view underneath on its own.
- `NSTextField.selectText` ends the field's editing before it selects, which fires `controlTextDidEndEditing`: a field that saves there closed before it showed (the marker list's rename). `makeFirstResponder` already selects the whole text.
- An `NSMenuItem` subclass must override `init(title:action:keyEquivalent:)` and not trap in `init(coder:)`: `ShortcutMenuPresentation` copies the items of every menu that opens, and AppKit's copy calls that initializer.
- Never call `super` in an override of a key-binding action (`cancelOperation`, `insertNewline`, …) on an `NSView`, `NSViewController` or `NSWindowController`: `NSResponder` doesn't implement them, so the call throws unrecognized selector and crashes. Pass it on with `nextResponder?.tryToPerform(_:with:)`.
- UI code owns presentation only and never touches Chromium internals; `ChromiumBridge/` adapts the framework without presentation logic.
- `BrowserState` is exactly one per window and owns tabs and lifecycle. Don't add a global state container.
- Remote API calls go through `Networking/APIClient.swift`, never a direct `URLSession`. Exceptions: `MistSyncClient`, whose token comes from the sync group key, and Mail's IMAP/SMTP.
- In an async function, don't hand an awaited call a closure with `[weak …]` captures of locals: release builds stack-promote the weak boxes, which read garbage after a suspension (failed and crashed `captureStill` only in installed builds). Capture strongly when the closure doesn't outlive the call.
- A loop that never leaves its GCD block (a pipe reader) wraps each iteration in `autoreleasepool`: `FileHandle.availableData` autoreleases a 16 KB page-aligned buffer per read, so without a pool every read stays alive until the block returns (`readAgentPipe`).
- Never start a nested modal run loop (`NSApp.runModal`, `beginModalSession`) from a main-actor task or a `DispatchQueue.main.async` block: the main-actor continuations it awaits starve. Use `RunLoop.main.perform(inModes:)`. A synchronous `NSAlert.runModal()` that awaits nothing is fine.

Strings:

- Follow `docs/i18n/localization-guidelines.md`: explicit key, English `value`, translator comment.
- Every new or reworded string ships in the same change with all 5 catalog languages in `Resources/Localizable.xcstrings` (`de`, `fr`, `ja`, `zh-Hans`, `zh-Hant`), reusing existing terms. App names are the exception: never catalog strings (Mist apps).
- Dropping a catalog language leaves an emptied `<lang>.lproj` in every incrementally built `build/DerivedData-*/…/Phi.app`, which still offers that language to macOS; delete those folders before installing.
- For a string Chromium also has, reuse its translations from the framework's `Resources/<locale>.lproj/locale.pak` (`zh_CN`, `zh_TW` for Chinese), found with `mist/scripts/pak.py <pak> list --find '<English text>'` (no `brotli` shim needed). Where Chromium's terms differ from the catalog's (ja ウィンドウ vs ウインドウ), keep the catalog's.
- Add catalog entries as text next to their siblings (the file is grouped by feature): its formatting doesn't survive a JSON load and re-dump. Review a catalog diff with `git diff --diff-algorithm=patience`: the default one shows a bulk deletion as thousands of inserted lines, which looks like a re-dump.
- A top-level plural variation compiles to `%#@value@` and pluralizes on argument 1, so a plural string with several arguments takes its count as `%1$d`.
- Write the English as upstream would, with `Phi`; the post-build rewrite makes it `Mist`.
- Give new catalog entries `"extractionState": "extracted_with_value"`, never `manual`: Xcode compiles a `manual` entry containing a format specifier into every other language as its raw key.

## Driving the running app

External agents connect over the app's agent CDP socket (`ChromiumBridge/AgentCDP/`) with the skill in `tools/phi-browser-skill/`. They need the Settings ▸ Advanced switch "Allow agents to control Mist"; while it's on, any local agent connects without a prompt (Drifter chats connect either way). They work in their own agent Space.

- The skill drives only one bundle: `PHI_BUNDLE_ID` if set, else the app it's linked into, else main Mist. Set `PHI_BUNDLE_ID=com.bulldf.mist.dev` for Dev; from a repo checkout the defaults reach main.
- AppleScript `open tab` turns `file://…` into `https://file///…` and `about:blank#x` into a search. Open a local file with `open -a "/Applications/Mist Dev.app" <file>`.
- `open -a "/Applications/Mist Dev.app"` brings Dev to the front; AppleScript `activate` can leave it behind a full-screen app. The password manager acts only while its window is key.
- The Mac's system language is French. To see Dev in English, quit it, run `defaults write com.bulldf.mist.dev AppleLanguages -array en`, and delete the key afterward. Never pass `-AppleLanguages` as a launch argument: Chromium may treat its value as a URL.
- `defaults write com.bulldf.mist.dev BrowserAgentIdleLifetime <seconds>`, read at launch, shortens the 5-minute idle lifetime of preview cards, folder tabs and Slack thread tabs, and the lifetime of clipboard items Dev sends, for a check; delete the key afterward. `DrifterBackgroundCheckInInterval <seconds>` (at least 10) likewise shortens the 30-minute background check-in.
- Switch layouts by quitting Dev, then `defaults write com.bulldf.mist.dev layoutMode <mode>`: `balanced` and `performance` have vertical tabs, `comfortable` horizontal. Coming back from `comfortable` this way hides the sidebar (press its toggle) and can drop a window's Drifter section header until relaunch.
- To trigger the save-password prompt, serve a local page whose prefilled login form calls `requestSubmit()` and navigates to a second page.
- Change bookmarks, pinned tabs, Spaces and URL rules through the skill's management helpers (`listBookmarks`, `removeBookmark`, …), which need no `enterContext`.
- Never edit `LocalStore.sqlite` while the app runs, nor Chromium's `Default/Bookmarks`, which is only a mirror.
- To probe a live tab's raw CDP in Dev, import `lib/helpers.mjs` in a node script with `PHI_BUNDLE_ID=com.bulldf.mist.dev`: `userFocus` → `enterContext({kind: 'user', window})` → `listSpaceTabs` → `switchTab(targetId)` → `withPageSession((client, sid) => …)`. This doesn't select the tab.

## Syncing with upstream

Take upstream only when it's worth it: Chromium or security updates, a feature Johnny likes, or a fix.

- Each framework release is built against upstream's client at that release, and the bridge header changes almost every release. Mist takes frameworks alone (Johnny's call; its last client merge was 2.14.0): it adopts the release's `PhiChromiumBridgeHeader.h` minus declarations of features Mist deleted, and ports only what that breaks onto Mist's model (the `framework-update` skill). A full merge happens only for upstream features Johnny wants, preferably as cherry-picks.
- A framework-only patch release (an upstream `release/X.Y.Z` branch at the same commit as the previous one) needs only the download script. A single feature can be cherry-picked.
- Before a sync, check upstream's most active area, the AI interface (`States/AgentSpace/`, `BrowserState+ToggleAI.swift`); Mist deleted the rest of Phi's AI client, so expect conflicts there.
- After a sync, run `install.sh --dev` and check that the branding still applies.
- Keep the framework zip of every version in use, as `Phi.Framework-vX.Y.Z.zip` in Johnny's Google Drive folder `Mist Frameworks` (My Drive): Phi's releases could disappear, and the framework repo grants no license.
- Turn on `git rerere` (`git config rerere.enabled true`) before resolving a sync.
- Syncs are rare, so a clean fix beats avoiding conflicts. Otherwise prefer new files and small hooks, and don't reformat or move upstream code.

Resolving conflicts:

- Keep every Mist deletion, including its hooks in shared files, and strip anything upstream newly wires to deleted code. `git log --oneline upstream/main..main -i -E --grep='^(remove|delete|strip|replace)'` lists them; `AGENTS.md` is gone too.
- Take only the OSS branch of a `#if !PHI_OSS_BUILD` conditional, and Mist's branch of a `DEBUG` or `NIGHTLY_BUILD` one (see above), as plain code.
- Exception: the Mist Chat panel keeps upstream's per-tab slot (`Tab.aiChatCollapsed`/`aiChatEnabled`, `setAIChatCollapsed`, split mirroring, the extension side panel mutex).
- Carry a new upstream build setting the OSS build needs into the `OpenSource` blocks.
- Never remove or reorder `BrowserType` cases or `ChromiumBrowserTypeKiosk*` in the bridge header; the framework is built against them.
- Keep SwiftData schema fields and historical migrations of removed features.
- `README.md` is rewritten for Mist; keep ours. About 45 user-visible `"Phi"` literals in Swift and their tests say `"Mist"`.
- Upstream's markdown renderer in `AgentTranscriptPanel.swift` moved to `Common/Markdown/MarkdownRenderer.swift`.
